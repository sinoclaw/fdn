# BDH 与 DCA 融合：判断与最小验证方案

## 0. 结论先行（爸爸要的判断）

**能融合。而且只有融合才可能达成"能力不输 + 训练/推理成本双降"。**

理由：
- BDH 与 DCA 是**两个层**，不冲突：BDH 是"单一能力的神经动力学单元"（长上下文、稀疏、状态在边权），DCA 是"能力生命周期管理"（复用/生长/免训练决策）。
- GPT 七审已明确：**BDH 是 DCA 的 Capability substrate**。
- 但 BDH **单独**实测：CPU 上训练贵5倍、推理贵3倍（能力≈Transformer）→ **单独 BDH 达不到"双降"**。
- 融合才有戏：DCA 的**稀疏激活（只用需要的 cap）** + **Interference Predictor（免训练决定用哪个 cap）** 理论上抵掉 BDH 单元的成本劣势 —— **但必须实测，不能靠推理**。

## 1. 融合架构

```
               DCA Capability Manager（能力生命周期）
                     ↓  (Interference Predictor 免训练决策：复用/新建/冻结)
      Capability 池:  [cap=BDH单元]  [cap=BDH单元]  [cap=BDH单元] ...
      `每个 cap 内部 = BDH`（fast weights + 稀疏乘法门控 + K-is-Q 因果注意）
```

- DCA 决定"用哪个 cap / 要不要新建"（省训练——免训练决策）
- BDH cap 决定"这个能力长上下文 / 稀疏怎么算"（省推理——稀疏激活）
- 稀疏激活：**每 token 只路由到需要的 cap** → 推理时不是全模型算 → 省算力

## 2. 最小验证：DCA 管理 BDH-cap，测能力 + 成本

**核心研究问题**：把 BDH 作为 DCA 的 cap substrate，DCA 的稀疏激活 + 免训练决策，能否让"能力不输 + 成本双降"成立？

### 判据（判据先行）：
- **判据 A 能力不输**：DCA+BDH-cap 在持续任务上，能力 ≥ 单 Transformer（不输）。
- **判据 B 成本双降**：
  - **B1 训练成本**：DCA+BDH-cap 总训练成本（wall-clock/FLOPs）≤ 单 Transformer。
  - **B2 推理成本**：推理时只激活需要的 cap → 单 token 前向成本 ≤ 单 Transformer。

### 实验设计（一次只动一组变量）：
1. 字符级任务序列（多技能，模拟持续学习）。
2. **对照组**：单 Transformer 训全部技能（能力基线，成本基线）。
3. **实验组**：DCA 动态池（按需 spawn/复用）管理多个 BDH-cap，每技能路由到需要的 cap。
4. 测：A 各技能能力；B 总训练时间 + 单步推理时间。

### 诚实边界：
- BDH cap 本身在 CPU 上可能仍比 Transformer 单元贵（慢5倍）；**融合的关键看 DCA 的"只用需要的 cap"能不能整体抵掉**。
- 若融合后仍"能力输或成本贵" → 如实记录，判定"BDH+cap-substrate 融合在当前 CPU 配置下未达成双降"，定位根因。
- 不预设结论，不硬凑。

## 3. 与父目标对齐
父目标 = "找区别于 Transformer 的范式，能力不输 + 训练/推理成本双降"。
- BDH 单独：能力≈但不降本（已实测）。
- BDH+DCA 融合：是让"降本"成立的**唯一可能路径**（稀疏激活只算需要的 cap）。
- 本实验直接检验融合能否达成，是父目标的关键一步。

## 4. 达标的下一步（预锚定）
若融合达成"能力不输 + 双降" → 走通，进入父目标下一步：找对标模型 → 蒸馏 → 对打。
